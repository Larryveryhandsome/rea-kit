## 一、擴展性

### 已確認沒問題（附證據）

- **租戶隔離**：每位仲介的租戶代號由 LINE 簽章過的 userId 決定（`adapters/line/shared.py:169` 雜湊、或管理員發的綁定碼），訊息內容沒辦法指定別人的租戶；所有檔案路徑經 `adapters/storage.py` 的 `validate_tenant_id`＋路徑跳脫檢查。測試：`tests/test_review_shared_isolation.py`（他人不能用編號碰客戶、換綁後舊租戶碰不到、群組不能操作）、`test_admin_invites_new_member_with_separate_data`。
- **同店多位經紀人**：每人一個獨立租戶（客人、物件互相看不到）；加人＝管理員面板按「＋ 邀請新成員」→ 給 6 碼 → 對方加好友傳 6 碼，全程點選與輸入。
- **新客戶**：LINE「新增買方」點選精靈、或 Google 試算表每日同步，不用改設定檔。
- **推播不會失控**：整個官方帳號一本帳（`adapters/line/push_budget.py`）、每位仲介每天最多 3 則、每月公平份額 90 則（`shared.py:79`）；額度依 LINE 方案每天自動同步。
- **重複推播**：主動推播帶 `X-Line-Retry-Key`，佇列重送用同一把 key（`adapters/line/push_gate.py:134`、`client.py` 409 視為已送）；今日報告「真的送到才記看過」。

### 容量估算（給主機租用定價參考）

| 項目 | 數字 | 說明 |
|---|---|---|
| 一個服務程序的記憶體 | 約 **41 MB**（閒置，實測 Windows／Python 3.14） | 一個程序服務一個 LINE 官方帳號 |
| 一台 2 GB 小主機 | 保守 **20～30 個客戶程序** | 每客戶獨立 PORT＋`REA_DATA_DIR`，互不影響；留一半給系統與高峰 |
| LINE 免費方案 | 200 則／月 ≈ **6 位仲介**每天一則報告 | 超過要升級 LINE 方案（費用客戶自付）；管理員面板會提醒 |
| 搜尋服務預設上限 | 全站 200 次／天、每人 40 次／天 | 每位仲介每天報告約 10～30 次 → 一個帳號約 **7～15 位**；可調 `REA_SEARCH_DAILY_CAP` |
| 儲存 | JSON 檔，每位仲介約數百 KB | 百位以內沒問題 |

### 🟡 先列出

- **團隊共用客戶**：同店的人目前不能共用買方清單（各自獨立）。要做「團隊」需要新的資料結構。
- **JSON 檔儲存**：同一個帳號超過約 100 位仲介時，`bindings.json` 等單一檔案的鎖會變慢；那時應換資料庫（只要換 `adapters/storage.py`）。
- **排程單執行緒**：所有仲介的今日報告在同一條執行緒依序跑；每人 10～30 次搜尋，人很多時最後幾位會晚一點收到。
- **webhook 去重只在記憶體**：服務重開後 LINE 若重送同一事件會再處理一次（回覆權杖已失效，所以不會重複回覆，但草稿可能多走一步）。
- **一個程序一個官方帳號**：代管多客戶時要開多個程序（目前靠 PORT／REA_DATA_DIR 分開），還沒有一鍵開新客戶的管理工具。

## 二、程式漏洞

### 已確認沒問題

- **webhook 簽章**：沒 secret 或沒簽章一律拒絕、常數時間比對（`adapters/line/signature.py`）；body 上限、JSON 錯誤回 400；入口限流（`web/beta_ingress.py`）。
- **/admin 權限**：只有 `REA_ADMIN_USERS` 的 LINE 帳號能在 LINE 拿 10 分鐘、一次性的登入連結；Cookie `HttpOnly; Secure; SameSite=Lax`；所有動作驗表單碼（CSRF）；管理員被移除後舊 session 立刻失效（每次請求都重查名單）。測試：`tests/test_admin_panel.py`。
- **XSS**：管理員面板所有輸出走 `html.escape`；精靈頁面結果一律 `textContent`；服務條款頁內容來自 repo 檔案。
- **SQL injection**：沒有使用 SQL。
- **SSRF**：精靈只會連固定網域（LINE、docs.google.com、內政部、搜尋服務），試算表網址用正規表示式限定 Google；不跟轉址（金鑰不會被帶去別的主機）；LINE API base 只准 https 或本機。
- **金鑰存放**：Windows DPAPI 加密、其他系統 600 權限（`adapters/settings_store.py`）；任何 API 都不回傳金鑰（測試 `test_line_full_flow_with_real_signature_check` 檢查狀態裡沒有 secret／token）。
- **log 不洩漏個資**：系統稽核只記事件種類（不記 LINE ID、不記內容，`test_shared_mode_keeps_no_raw_chat_and_audit_has_no_line_ids`）；精靈錯誤只回「發生沒預料到的錯誤（類型）」，traceback 只進本機 `server.log`（`web/setup_wizard.py:327`，Python traceback 不含變數值）；Waitress 預設不記存取紀錄，所以網址裡的一次性碼不會落檔。
- **管理員碼**：6 碼、10 分鐘、錯 5 次作廢（`web/setup_claim.py:39`）。
- **local-helper**：目前**沒有任何程式**，沒有攻擊面。未來做的時候要守：只在使用者電腦、只操作使用者自己登入的瀏覽器、不收網路指令、更新檔要簽章。

### 🟡 先列出

- **Mac／Linux 的金鑰是明文**（600 權限）：要更安全可接系統鑰匙圈（Keychain／libsecret）。
- **管理員 session 與進入碼存明文 JSON**：在本機資料夾、非公開，但若主機被入侵可被拿來登入；可改存雜湊。
- **精靈換 LINE 金鑰時立即生效**：若貼了錯的 secret，在第 4 步測出來之前機器人會暫時不通（畫面會明講）。

## 三、串接狀況（每一步失敗時）

| 狀況 | 怎麼處理 | 測試證據 |
|---|---|---|
| LINE token 貼錯／過期／被重發 | 精靈：白話「token 不對或已失效＋如果按過 Reissue 要貼新的」；執行中：每天檢查，失效就在精靈頂端紅字 | `test_line_full_flow_with_real_signature_check`、`test_revoked_line_token_shows_in_wizard_health`；瀏覽器實測真實 LINE 回 401 |
| secret 錯（webhook 驗簽失敗） | 第 4 步 LINE 真的打一次，回「簽章對不上：Channel secret 填錯」；不會改掉原本的 LINE 設定 | `test_failed_webhook_test_does_not_touch_line_setting` |
| 網址打錯、DNS、憑證、服務沒開 | 依 LINE 回的原因分別說明 | `test_webhook_test_failures_are_plain_language` |
| 「Use webhook」沒開 | 告訴他去哪裡切 | `test_line_full_flow_with_real_signature_check` |
| Google 授權撤銷（取消共用） | 精靈：「還沒開放連結檢視＋怎麼開」；每日同步失敗記健康狀態、紅字 | `test_sheet_urls`、`test_google_sheet_check_save_and_sync`、`test_health_banner_data`；瀏覽器實測真實 Google |
| 591／樂屋改版 | 我們不爬平台，走搜尋服務 API；平台改網址格式時「新物件」會變少但不會出錯 | 🟡 見下 |
| 591／樂屋限流 → 搜尋服務額度／限速 | 當天自動停用不重試、精靈紅字；換新金鑰立即恢復 | `SearchHealthTests`、`test_new_search_key_lifts_todays_stop`；瀏覽器實測真實 Brave 回 422 |

### 🟡 先列出

- **平台網址格式寫死**：`core/market_sources.py:41` 起每個平台的物件網址規則是正規表示式；平台改版時要更新規則。建議加一個每週的「各平台抽樣 0 筆」提醒。
- **實價登錄政府網站改版**：下載網址是政府公開格式（`adapters/integration_checks.py` 的 `LVR_BASE`），改版時精靈會顯示「最近幾季都抓不到資料」，但需要人更新程式。
- **地政平台回應格式**：目前只依公開文件與另一個工具的經驗解析，**還沒用正式金鑰實測**（README 已標示）。

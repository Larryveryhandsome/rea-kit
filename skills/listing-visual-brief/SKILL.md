# 物件 → 美編／AI 圖像需求單

> 本 skill 只產需求單與檢查結果。不上傳照片到任何平台、不發文。圖上的每個數字都要和文案同一組。

## 參數

- 物件事實卡（同 listing-copywriter，只取已確認欄位）：`{物件代號}`、`{縣市}`、`{行政區}`、類型、總價、坪數、格局、樓層、屋齡
- 照片清單：檔名、拍攝內容、拍攝日期、是否本物件實拍
- 品牌：`{經紀業名稱}`、`{加盟店標示}`、`{品牌主色}`、`{品牌輔色}`（最多 2–3 色）、`{標題字體}`、`{內文字體}`、`{標誌檔}`
- 輸出目標：`fb_feed`／`fb_link`／`ig_feed`／`threads`／`story`／`line_flex`／`line_imagemap`／`listing_site`／`print_dm`
- 風格：`克制質感`（預設：大面積淡色底、細線分隔、不用表情符號，圖示用線條）／`明亮生活感`／`數據資訊卡`

## SOP（標準流程）

1. **照片盤點**：只收本物件實拍，記錄拍攝日期。超過 6 個月、或屋況已改變（重新裝修、家具搬空），提醒補拍。沒有照片時，圖卡寫「照片準備中」，不用灰色假圖或網路圖填位置。
2. **隱私篩檢**：每張照片標「可用／需遮蔽（寫遮哪裡）／不可用」，依「永遠不能出現」逐項看。
3. **移除照片位置資訊**：交件前所有照片要清掉拍攝地點等檔案資訊（EXIF 的 GPS），避免從檔案反推門牌。
4. **排照片順序並選封面**（見下表）。
5. **定圖上文字**：只用事實卡已確認的數字，與 listing-copywriter 產出的文案逐字比對。
6. **列尺寸與安全邊界**：依輸出目標列出每一張要做的尺寸。
7. **產出**：給人的需求單，或給 AI 工具的提示；兩者都附「禁止事項」與「交件檢查」。
8. **收件驗收**：把成品實際轉成圖片看過（不是只看設計檔），跑交件檢查；不合格退回，寫清楚第幾張、哪一點。

## Decision points（判斷要點）

### 照片順序（預設，可依物件調）

| 類型 | 封面 | 之後依序 |
|---|---|---|
| 公寓／華廈／大樓 | 客廳最明亮、最有代表性的一張（或景觀） | 客廳其他角度 → 餐廳廚房 → 主臥 → 次臥 → 衛浴 → 陽台／景觀 → 公設 → 社區外觀（無門牌）→ 周邊機能 → 格局圖 |
| 透天／別墅 | 外觀正面（遮門牌、車牌） | 客廳 → 廚房 → 各樓層臥室 → 衛浴 → 頂樓或露台 → 車庫 → 周邊 → 格局圖 |
| 店面 | 街面外觀（遮他人招牌、車牌、路人） | 內部空間 → 面寬與騎樓 → 後場與衛浴 → 樓上空間 → 周邊街景（無人臉） |
| 土地 | 現場全景或空拍（地界線標「示意」） | 臨路照 → 面寬 → 周邊環境 → 位置示意（只到區域）→ 使用分區資訊卡 |
| 租屋 | 主要生活空間 | 臥室 → 衛浴 → 廚房與洗衣 → 設備（冷氣、熱水器）→ 外觀 → 周邊 |

原則：
- 封面要「真實的最好一面」，不用沒有代表性的局部特寫。
- 同一空間最多 3 張；先廣角、再細節。
- 格局圖一律重繪，不放原始圖面上的地址、地號、屋主名；重繪圖標「示意，以實際丈量為準」。

### 圖上文字規則

- 封面最多 3 行：① `{行政區}`＋類型 ② 總價（只放一個數字，單位「萬」）③ 一個賣點（10 字以內）。
- 必放：`{經紀業名稱}`（加盟店含 `{加盟店標示}`）放在角落，小但手機上看得清楚。
- 示意圖、虛擬家具、合成背景、重繪格局圖：圖上一定要有「示意」字樣。
- 不放：精確地址、屋主資訊、驚嘆號、listing-copywriter 的「法遵禁用」與「誇飾」詞、「低於行情」「全區最低」、「限時」「最後機會」。
- 文字總面積建議不超過畫面 1/4；字與底色對比要夠，照片上的字加半透明底塊。
- 手機可讀：最小字高不低於畫面寬度約 3%（1080 寬約 32px）。
- 標題放不下就改短，不截字。成品不可出現「undefined」「NaN」「null」、亂碼、殘留程式標籤或範本參數（例如 `{總價}`）。
- 價格、坪數、房數在「圖、文、物件網頁」三處一致。

### 各平台尺寸（平台規格常變，以平台當下官方說明為準）

| 輸出目標 | 建議尺寸（像素） | 比例 | 備註 |
|---|---|---|---|
| FB 動態 | 1080×1350 | 4:5 | 主力尺寸，手機上佔版面最大 |
| FB／Threads 連結預覽 | 1200×630 | 1.91:1 | 文字集中在中央，邊緣可能被裁 |
| IG 動態 | 1080×1350（或 1080×1440） | 4:5（或 3:4） | 多張時封面放第一張 |
| Threads 圖片 | 1080×1350 或 1080×1080 | 4:5／1:1 | 多張時封面放第一張 |
| 限時動態／短影音封面 | 1080×1920 | 9:16 | 上下各約 250px 不放字與標誌 |
| LINE Flex 主圖 | 1040×676 或 1040×1040 | 20:13／1:1 | 聊天室縮圖小，字要更少更大 |
| LINE 進階圖文訊息 | 寬 1040 | 依版型 | 可點區塊不要壓在文字上 |
| 售屋網站 | 長邊 ≥ 1600 的原圖 | 多為 4:3 橫式 | 直式照片常被裁切，上傳前先看預覽 |
| 列印 DM | A4（210×297 mm） | — | 300 dpi、出血 3 mm、CMYK、文字離裁切線 ≥ 5 mm |

**安全邊界**：數位圖四邊各留約 5%（1080 寬約 54px），不放重要文字與標誌。

### 永遠不能出現（隱私與安全）

- 門牌號碼、樓層戶號、信箱或對講機上的名字、社區門口的住戶名牌
- 車牌（停車場、車庫、街景）
- 人臉：屋主、家人、房客、鄰居、路人、同事；仲介本人入鏡要本人同意
- 屋主身分線索：全家福、獎狀、證書、信件包裹、帳單、藥袋、行事曆、白板、孩童名牌、可辨識個人的宗教或政治物品
- 安全資訊：門禁密碼、鑰匙、保全面板、監視器位置、保險箱、貴重物品放置處
- 螢幕內容：電腦、手機、電視畫面上的文字
- 文件：權狀、登記謄本、不動產說明書內頁、含完整地號的地籍圖（地號只到段）
- 地圖：精確定位點；位置示意只畫到區域或路段
- 他人著作：其他仲介或平台的照片、帶浮水印的圖、圖庫照片冒充實景

### 修圖界線

- **可以**：調曝光、白平衡、水平與鏡頭變形校正；遮蔽隱私（模糊、馬賽克、色塊）；保守移除暫時雜物（例如垃圾袋）。
- **不可以**：修掉壁癌、裂縫、漏水痕、電線桿、高壓電塔、鄰近嫌惡設施；換天空讓採光看起來更好卻不標示；拉寬空間比例；把增建修成原建物的樣子。
- **虛擬家具／AI 補景**：必須標「示意」，並同時提供原始照片給買方看。

### 給 AI 圖像工具的界線

- 只用在：版面、底圖、線條圖示、資訊卡、清楚標示「示意」的生活情境圖。
- 不要求 AI 生成「本物件」的外觀或室內當作實景；不要求 AI 擴圖補出不存在的空間或景觀。
- 提示裡不放地址、屋主資訊、人名。

## Checklist（檢查清單）

- [ ] 每張照片都標了可用／需遮蔽／不可用，遮蔽位置寫清楚。
- [ ] 照片的拍攝地點資訊已清除。
- [ ] 封面與順序符合物件類型；格局圖已重繪並標示意。
- [ ] 圖上數字與文案、物件網頁一致。
- [ ] 經紀業名稱（加盟店含加盟標示）已放；示意圖已標「示意」。
- [ ] 尺寸、安全邊界符合每個輸出目標。
- [ ] 沒有禁用詞、驚嘆號、範本參數殘留、亂碼。
- [ ] 成品已實際轉成圖片檢視過。

## Template（範本）

### 給美編的需求單

```text
物件代號：{物件代號}｜{縣市}{行政區}｜{類型}
輸出：{fb_feed 1080×1350、fb_link 1200×630、line_flex 1040×676 …}
風格：{克制質感}；主色 {品牌主色}、輔色 {品牌輔色}；字體 {標題字體}/{內文字體}

封面：{照片檔名}（{理由}）
圖上文字（逐字）：
  1. {行政區}・{類型}
  2. {總價} 萬
  3. {賣點，10 字內}
  角落：{經紀業名稱}{加盟店標示}

照片順序：
  1. {檔名}｜可用
  2. {檔名}｜需遮蔽：{右下門牌}
  3. {檔名}｜不可用：{牆上全家福，無法遮}
  …

必須標「示意」：{重繪格局圖、虛擬家具圖…}
禁止：門牌、車牌、人臉、屋主資訊、權狀謄本、精確定位、修掉屋況瑕疵、圖庫照片
交件：每個尺寸一張 PNG，檔名 {物件代號}_{輸出目標}_{序號}.png
```

### 給 AI 圖像工具的提示

```text
請設計一張 {寬}×{高} 的房地產物件資訊卡版面。
風格：{克制質感}，主色 {品牌主色}、輔色 {品牌輔色}，線條圖示，不用表情符號。
上方 60% 保留給實拍照片（我會自行放入，不要生成房屋影像）。
下方文字區（逐字使用，不要改寫、不要加字）：
  「{行政區}・{類型}」「{總價} 萬」「{賣點}」
右下角小字：「{經紀業名稱}{加盟店標示}」
四邊各留 5% 空白不放文字。不要出現任何地址、人物、車牌、驚嘆號。
```

## Output requirements（輸出要求）

- 先給照片盤點表（含遮蔽與不可用原因），再給需求單或 AI 提示，最後給交件檢查清單。
- 使用者要求修掉屋況瑕疵或用 AI 生成假實景時，說明不做的原因，並提供可以做的替代方式（調光、標示意的情境圖）。
- 不宣稱已上傳、已發布。

## Test cases（測試案例，全部為合成資料）

**T1 大樓 20 張照片：** 示範市河濱區大樓，其中 1 張拍到門牌、1 張牆上有全家福、2 張停車場拍到車牌。期望：門牌與車牌標「需遮蔽」並寫位置；全家福那張若無法遮則「不可用」；封面選客廳；列出 FB 1080×1350、1200×630、LINE 1040×676 三種尺寸；提醒清除照片位置資訊。

**T2 土地：** 示範市山腳區農地，有空拍照與一張地籍圖截圖（含完整地號）。期望：空拍當封面、地界線標「示意」；地籍圖截圖不可用，改做「使用分區資訊卡」只寫到段；位置示意只到區域。

**T3 要求修瑕疵：** 使用者說「把主臥牆角的壁癌修掉，看起來比較好賣」。期望：拒絕並說明這會讓買方誤認屋況；改建議調整曝光、換拍攝角度不刻意遮掩，並在文案照實揭露屋況。

**T4 AI 生實景：** 使用者說「這間還沒拍照，用 AI 生一張外觀先發」。期望：不生成本物件實景；改提供標「示意」的資訊卡版面，或在圖卡寫「照片準備中」。

**T5 數字不一致：** 圖卡寫 1,380 萬，文案寫 1,350 萬。期望：交件檢查擋下，退回並指出不一致，以事實卡為準。

**T6 範本殘留：** 成品圖上出現「{賣點}」與「NaN 坪」。期望：交件檢查擋下，列出殘留的位置。

## Acceptance criteria（驗收標準）

- 每張照片都有明確狀態，任何「永遠不能出現」的項目都已遮蔽或排除。
- 圖上文字與文案、事實卡一致，且無禁用詞。
- 每個輸出目標都有尺寸與安全邊界；示意內容都已標示。
- 不提供修掉瑕疵或偽造實景的方法；成品可直接交給美編或 AI 工具執行。

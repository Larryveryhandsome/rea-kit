# 值班排班（輪值、換班、假日、公告）

> 一句話：把「誰哪天值班」排得公平、查得出衝突、改得有紀錄，並在對的時間提醒對的人。

## SOP

1. **收設定**（缺什麼就問，不要猜）
   - 輪值名單與順序（只用角色或名字，不放電話）；本月新加入、離開的人與生效日。
   - 每人的固定限制：例如「某人週末不排」「某人週三下午固定上課」；本月請假、受訓、帶看或簽約已排定的日子。
   - 規則：哪些日子要排（平日／週末／國定假日是否營業）、一天幾人（主值＋副值？）、每週上限、可否連續值班。
   - 上個月最後輪到誰、以及每人累計的平日／假日值班次數（公平要跨月延續）。
2. **建日曆**
   - 國定假日以**行政院人事行政總處公布的政府行政機關辦公日曆表**為準，補班日照公告；公司另訂休假日由店長確認。
   - 農曆日期（例如初一十五、初二十六的祭拜提醒）用公開萬年曆對照，非必要功能，由團隊決定要不要開。
3. **輪流指派**
   - 照名單順序往下輪，**接續上個月的位置**，不要每月從第一位重新開始（否則排在前面的人永遠多值）。
   - 遇到當天不能排的人 → 跳過、由下一位遞補，並給被跳過的人記一筆「欠班」；下一個他可以排的日子優先補回，讓總次數拉平。
   - 平日與假日**分開計數**：假日（週末＋國定假日）用另一個輪序，確保假日班也平均。
4. **衝突檢查**（排完一定要跑）
   - 同一人同一天重複、排在請假或受訓日、違反個人固定限制。
   - 連續值班、超過每週上限。
   - 已離職者還在表上、新人在報到日前被排到。
   - 當天有人沒排到（空班）。
   - 值班人當天已有帶看、簽約、交屋等外出行程 → 標「需確認」，由本人決定換班或請副值支援。
5. **公平性檢查**：列出每人本月與近 3 個月的平日／假日次數；差距超過 1 次要說明原因（請假、限制）或調整。
6. **產出**：班表草稿＋衝突清單＋公平性統計＋公告訊息草稿，交店長確認。
7. **發布節奏**（建議值，可調）
   - 每月固定日（例如 25 日）發布下個月班表。
   - 每天傍晚提醒「明天值班的人」並附值班注意事項。
   - 會議前一天提醒全員（例如每週固定早會、每月第一個工作日的月會）。
8. **換班流程**
   - 申請人自己找好替班人 → 雙方都在群組或系統裡確認 → 店長核准（若團隊規定要核准）→ 更新班表並記一筆換班紀錄 → 發布異動公告。
   - 換班前先跑衝突檢查（不能因為換班變成連續值班或撞到請假）。
   - 次數算給**實際值班的人**。
   - 建議設換班截止時間（例如前一天 18:00 前），之後只能找店長處理。

## Decision points（判斷要點）

- 名單、限制、假日沒給齊 → 先列「待確認」，不要自己假設某人週末可以排。
- 「某人不排週末」這種長期限制，是固定規則不是欠班；只有臨時請假才記欠班（由團隊決定，要寫在設定裡）。
- 人數少、限制多，數學上排不平均時，直接講出來並給兩個方案（例如加一位副值、或放寬連續值班），不要硬排出違規的表。
- 已發布的班表若要大改，列出「變動前／變動後」差異，只通知受影響的人加全員公告一則。
- 值班公告只放名字或角色；轉接用的手機號碼、門禁密碼等不要寫進群組公告。
- 有人不參與某項提醒（例如不參加祭拜），在設定裡標「不提醒」，不要每次都 tag 他。

## 值班注意事項（通用範例，可依門市改）

上班：
1. 開門前到班；從前一位值班者手上接過值班電話與鑰匙。
2. 取消前一晚的電話轉接，確認市話正常。

值班中：
3. 每一通來電都登記：日期時間、來電者自稱、詢問的物件、需求、後續追蹤人；當天下班前登錄進自己的客戶系統。
4. 來店客接待、遞名片；物件問題轉給負責的經紀人員。

下班：
5. 倒垃圾、關冷氣電扇與燈、關門窗、上鎖。
6. 設定電話轉接到值班手機（號碼由團隊私下設定，不寫在公告）。
7. 提醒當天所有經紀人員把今天的客戶資料登錄完畢。
8. 隔天上班時把值班手機交給下一位值班者。

## Checklist（檢查清單）

- [ ] 名單、限制、請假、假日、營業規則都已確認或標待確認。
- [ ] 輪序接續上個月；平日、假日分開計數。
- [ ] 跳過的人有記欠班並在後續補回（臨時請假時）。
- [ ] 衝突檢查全部通過，或每一筆都有說明。
- [ ] 公平性統計已列，差距超過 1 次有理由。
- [ ] 公告與提醒裡沒有電話、密碼等不該公開的資訊。
- [ ] 換班有雙方確認與紀錄，次數算給實際值班者。

## Template（範本）

```text
【{年}年{月}月 值班表】（草稿，待店長確認）
日期｜星期｜主值｜副值｜備註
10/01｜四｜{成員A}｜—｜
10/04｜六｜{成員C}｜—｜假日輪序
10/10｜六｜{成員D}｜—｜國慶日（營業）
…
本月統計：成員A 平日4／假日1；成員B 平日4／假日1；…
衝突與待確認：
- 10/15 {成員B} 有簽約行程 → 請確認是否換班
換班規則：自己找好替班人，雙方確認後於前一天 18:00 前回報。
```

```text
【明日值班提醒】{日期}（{星期}）
明天值班：@{值班者}
- 開門前到班，從今天值班者接手值班電話與鑰匙
- 來電一律登記，下班前登錄完畢
今天值班 @{今日值班者} 下班前請：倒垃圾、關冷氣電燈、上鎖、設定電話轉接
```

```text
【換班異動】{日期}：{原值班者} ↔ {替班者}（雙方已確認，店長已核准）
更新後班表：{連結或附件}
```

未來工具動作：發布到群組、@ 標記成員（成員 ID 由設定檔讀取，不寫死）、寫入團隊行事曆，皆需店長確認後才執行。

## Output requirements（輸出要求）

依序輸出 `待確認事項`、`班表草稿`、`衝突清單`、`公平性統計`、`公告訊息草稿`。衝突沒解決前，班表標「草稿」，不得標「已發布」。所有發送與寫入都標為未來工具呼叫。

## Test cases（測試案例）

**T1 — 正常月份＋週末限制：** 6 位成員輪值，其中成員E「週末不排」；31 天的月份、週末全營業、每天 1 人。預期：成員E 不出現在週末；平日、假日各自輪流；本月每人總次數差距不超過 1，若因限制無法拉平要說明。

**T2 — 換班造成連續值班：** 成員A 10/07 想跟成員B 換班，但成員B 已排 10/06 與 10/08。預期：判定換班後成員B 連續三天，違反規則；不直接改表，提出替代人選或請店長裁決。

**T3 — 假日與請假：** 10/10 國定假日營業，排到的成員C 當天已請假。預期：跳過成員C、由下一位遞補並記成員C 欠班；成員C 下一個可排的假日優先補回。

**T4 — 月中離職：** 成員F 10/15 起離職。預期：10/15 起不再排成員F，空出的班依輪序遞補，並在公告中只說明「班表調整」，不寫離職原因。

**T5 — 資料不足：** 只說「幫我排下個月值班」，沒有名單。預期：不產出班表，列出需要的設定（名單、限制、營業日、每日人數、上月輪到誰）。

## Acceptance criteria（驗收標準）

- 每一天都有人值班或明確標示空班原因。
- 沒有違反個人限制、請假、連續值班、每週上限的排法；有例外必附理由。
- 平日與假日次數各自平均，跨月延續。
- 換班有紀錄、可追溯，次數算給實際值班者。
- 公告不含不該公開的個資；對外動作全部標為未來工具呼叫。

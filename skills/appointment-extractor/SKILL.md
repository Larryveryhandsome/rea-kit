# 行程抽取器（對話 → 待確認行程清單）

> 一句話：從仲介自己的對話裡，把「已經約好的事」挑出來、算好日期時間、去掉重複，排成一張仲介逐筆按確認的清單——沒按確認的，一筆都不進行事曆。

> 本技能只讀對話、產出清單。寫入行事曆、CRM 或回覆對方，都是需要仲介逐筆確認的未來工具動作。

## 參數（租戶設定）

| 項目 | 預設 | 說明 |
|---|---|---|
| 讀取範圍 | 仲介本人參與且授權的群組與一對一 | 租戶可再標「不讀」的群組（例如私人家庭群） |
| 處理單位 | 一個對話 × 一個日曆日 | 每行格式 `HH:MM 發言者代號：內文` |
| 每段上限 | 最近 150 行 | 太長只取當天最後 150 行，並標註已截斷 |
| 時區 | 台灣時間 | 所有日期時間以此為準 |
| 觸發字表 | 見判斷要點 B | 租戶可增修 |

## SOP（標準流程）

1. **確認範圍**：只處理授權範圍內的對話；遇到標「不讀」的群組直接略過，不列出內容。
2. **切段**：每個對話依「訊息日期」切成一天一段，每行保留時間與發言者代號。
3. **預篩**：該段沒有任何觸發字（判斷要點 B）→ 不送 AI 分析，省成本也降低誤抽。
4. **抽取**：依判斷要點 A 的準則，只抽已敲定的行程，每筆照「輸出欄位」填。
5. **換算時間**：相對時間一律以**該訊息的日期**為基準換算（不是以今天處理的日期），規則見判斷要點 C；算不出來填 null，不猜。
6. **改期與取消**：同一段或後續對話出現「改到…」「延期」「取消」「不約了」→ 更新對應行程的狀態，保留原句與新句。
7. **去重**：跨群組、跨日把同一件事合併（判斷要點 D）；有衝突的不合併，標「時間不一致」。
8. **排序**：有日期的依日期、起時間排；日期為 null 的放最後「待補時間」區。
9. **交給仲介確認**：每筆三個選項——確認／修改／丟棄。只有「確認」的可以交給行事曆工具，而且仍是逐筆、由仲介按下。

## Decision points（判斷要點）

### A. 要抽、不要抽

**要抽**（雙方已同意時間，或仲介本人已確認要做）：
- 簽約、帶看、約看、收斡旋或要約、對保、交屋或點交、勘查、拜訪屋主、開發投遞、會議或月會、回報、追蹤電話、與地政士或銀行的約。
- 確認訊號：對方回「好」「OK」「可以」「就這樣」「到時見」，或仲介本人寫「我會到」「確定」。

**不要抽**：
- 還在構想或詢問：「下週找時間看看」「您哪天方便？」（還沒回）。
- 純閒聊、轉貼連結、法規宣導、收費或廣告通知。
- 別人之間的約、與仲介無關的活動（除非仲介被要求出席）。
- 已經過去且沒有後續的事（例如昨天的帶看心得），除非仲介要求補登紀錄。

### B. 觸發字（預篩用）

```text
活動：簽約 帶看 約看 看屋 斡旋 收斡 要約 對保 交屋 點交 勘查 現場 拜訪 見面 碰面 面交 投遞 開發 回報 追蹤 會議 開會 晨會 月會
時間：今天 明天 後天 大後天 禮拜 星期 週 下週 這週 幾點 幾號 上午 早上 中午 下午 傍晚 晚上 點到 點去 號去
```

- 預篩只是省成本，**不是判斷**：有觸發字不代表有行程，沒觸發字的段落才跳過。

### C. 時間換算

| 原文 | 換算（基準＝訊息日期） |
|---|---|
| 今天／明天／後天／大後天 | 基準日 +0／+1／+2／+3 |
| 這週五、禮拜五 | 基準日所在週（週一到週日）的週五；若已過去，標「可能指下週，待確認」 |
| 下週一、下禮拜一 | 基準日所在週的下一週的週一 |
| 10 號、10/15 | 本月或指定月份；若已過去且沒寫月份，標「可能指下個月，待確認」 |
| 早上九點／上午十點 | 09:00／10:00 |
| 中午 | 12:00 |
| 下午三點、三點半 | 15:00、15:30 |
| 晚上七點 | 19:00 |
| 三點（沒說上下午） | 依活動判斷可能是 15:00，但**信心降為中**並標「上下午待確認」 |
| 傍晚、晚一點、月底、改天 | 時間或日期填 null，放「待補時間」 |

- 「兩點到四點」→ 起 14:00、迄 16:00；只有起點 → 迄時間 null，不自己加一小時。
- 換算後一律寫成 `YYYY-MM-DD` 與 `HH:MM`，並保留原文。

### D. 去重與衝突

- **同一件事**：日期相同＋起時間相同（或差 30 分鐘內）＋活動類型相同＋對象或物件相同 → 合併，保留所有原句與來源對話。
- **時間不一致**：同一對象同一活動出現兩個時間（例如 10:00 與 10:30），不合併、不自己選，兩筆都列並標「時間不一致，請確認」。
- **改期**：舊時間標「已改期」，新時間為有效行程；兩筆都保留，舊的預設不勾。
- **取消**：標「已取消」，預設不勾，保留原句。

### E. 信心

| 信心 | 條件 | 預設 |
|---|---|---|
| 高 | 日期與時間明確＋有確認訊號 | 勾選 |
| 中 | 時間明確但確認訊號不清楚；或上下午靠推斷 | 不勾，請仲介看 |
| 低 | 日期或時間有一項為 null；或只有單方提議 | 不勾，放「待補時間」 |

### F. 隱私

- 對象用對話中的稱呼或客戶代碼，不補電話、身分證或完整地址；物件用物件代號或案名。
- 原句只節錄最關鍵的一兩句，不整段複製。
- 清單只給仲介本人看；不轉貼到群組，不交給第三方。

## Checklist（檢查清單）

- [ ] 只處理授權範圍內的對話；「不讀」群組沒有出現在輸出。
- [ ] 每筆都是已敲定或仲介確認要做的事；構想與詢問沒有被抽出。
- [ ] 相對時間以訊息日期為基準換算；算不出來是 null，沒有猜。
- [ ] 每筆都有類別、子類別、日期、起迄時間、對象、物件、內容、信心、原句、來源。
- [ ] 重複已合併；時間不一致的兩筆都保留並標示。
- [ ] 改期與取消有更新狀態。
- [ ] 沒有寫入行事曆、CRM，也沒有回覆任何人。

## Output requirements（輸出要求）

- 先一行結論（掃了幾段、抽出幾筆、幾筆待補時間、幾筆衝突），再給清單。
- 清單順序：有日期的依時間排 → 時間不一致 → 已改期／已取消 → 待補時間。
- 每筆都附原句與來源；沒有原句的不得出現。
- 對話裡沒有任何敲定行程 → 輸出空清單並說「這段對話沒有已敲定的約」，不硬湊。
- 結尾固定寫明寫入行事曆屬未來工具動作、需仲介確認、本次未執行。

## Test cases（測試案例，全部為合成資料）

**T1 相對時間：** 訊息日期 2026-10-02（五）20:14：「那就明天下午三點簽約」，對方回「OK」。期望：date 2026-10-03、start 15:00、type 簽約、信心 高。

**T2 以訊息日期為基準：** 同 T1 的對話到 10-04 才處理。期望：仍換算為 10-03（以訊息日期為準），並因已過去標示「已過期，是否補登紀錄？」。

**T3 構想不抽：** 「下週找時間帶您看看那間」，對方沒回。期望：不抽出。

**T4 跨群去重：** 客戶群與內部群都提到「週六 10 點帶看 {物件代號}」。期望：合併為 1 筆，source 列兩個來源。

**T5 改期：** 上午說「下午兩點對保」，下午說「銀行改到四點」。期望：14:00 那筆標已改期、不勾；16:00 為有效行程。

**T6 上下午不明：** 「禮拜六三點帶看」。期望：換算到該週六 15:00，信心 中，標「上下午待確認」。

**T7 預篩：** 一段只有貼圖與「謝謝」的對話。期望：不送分析，不出現在清單。

**T8 要求直接寫入：** 仲介說「抓到的直接幫我寫進行事曆」。期望：仍輸出待確認清單，說明寫入需逐筆確認；不宣稱已寫入。

**T9 時間不一致：** 同一位客戶同一天帶看，一則寫 10:00、另一則寫 10:30。期望：兩筆都列、標「時間不一致，請確認」，不自己選。

## Acceptance criteria（驗收標準）

- 抽出的每一筆都能在原句中找到「已敲定」的依據；構想、詢問、閒聊零誤抽。
- 相對時間換算以訊息日期為基準，同一輸入每次結果一致；不確定的一律 null 或降信心。
- 重複合併、衝突並列、改期取消有狀態。
- 輸出零多餘個資；只處理授權範圍。
- 沒有任何行程在仲介確認前被寫入行事曆或 CRM。
- T1～T9 全部符合預期。

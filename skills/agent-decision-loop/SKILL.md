# 自動化決策迴圈（人在迴圈中的分級與確認）

> 一句話：**能自己做的就做完，不能自己做的用一張按得完的卡問一次，做錯的事不重試到天荒地老。**
> 評量只有一條：**這件事讓仲介少做了什麼、多成交了什麼？** 答不出來的，就是自我滿足，不是工作。

## SOP（標準流程）

1. **定級**：照「自動化分級」表，判斷這件事屬於 L1、L2、L3 或禁止級。
2. **開跑前檢查煞車**：全域暫停開關有沒有開？這個流程今天跑了幾次（預設每日上限 24 次，問人的流程 12 次）？超過就不跑。
3. **執行**：
   - L1／L2：直接做，做完留紀錄。
   - L3：先過「對外審核」——逐則審，或用已核准的範本；沒核准就**只留紀錄、不送出**。
   - 禁止級：不做，改成「把需要人做的那一步寫清楚」交給仲介。
4. **看到停止訊號立刻停**：對方回 429（太多請求）、逾時暴增、回應變空、出現驗證碼——**當下就停**，不要「再撐一下跑完」。
5. **驗證結果**：用「產出有沒有真的變新、內容對不對」判斷成功，**不看程式回傳碼**（見判斷要點 C）。
6. **記失敗次數**：同一件事（同一個目標、同一個原因）失敗就 +1，成功就歸零。**連續 3 次失敗 → 停止自動重試**，做一張確認卡交給仲介，並**真的通知到他**（不是只寫進紀錄檔）。
7. **卡住或說明不清楚 → 問，不要猜**：用三顆按鈕的確認卡（見範本），把「我卡在哪」和「我打算怎麼做」一起給他。
8. **回報**：用白話寫「我做了什麼、影響什麼、要不要你決定」，附「怎麼複驗＋預期看到什麼」。

## Decision points（判斷要點）

### A. 自動化分級

| 級 | 意思 | 例子 | 怎麼處理 |
|---|---|---|---|
| **L1 只回報** | 讀資料、算結果、給仲介看，不改任何東西 | 今日新物件摘要、配對清單、委託到期提醒、每週賣方進展 | 自動跑 |
| **L2 動內部、可還原** | 改的是只有自己人看得到、改錯可以還原的東西 | 重跑失敗的排程、補抓資料、去重、把新客戶群補進內部名單 | 自動跑＋留紀錄；寫入前比對，發現會動到既有資料就中止 |
| **L3 對外** | 客戶、屋主、同業或大眾**看得到**的；或寫入外部系統 | 推物件給客戶、發社群貼文、寄開發信、寫進第三方 CRM | **預設要仲介確認**（逐則審或範本審，見 B） |
| **禁止級** | 不論誰授權都不由 AI 做 | 輸入帳號密碼或驗證碼、代按登入、在同業或總部的群組發言、刪除或覆蓋沒讀過的資料 | 不做；只寫清楚「只剩哪一步要本人做、做完會自動接回」 |

判斷不出級別 → 往**比較嚴**的那一級放。

### B. 對外內容怎麼審（L3）

- **判準**：這則訊息、這份文件、這個畫面，客戶有沒有可能看到？有 → 先過仲介這關。
- **逐則審**：每次內容都不一樣的（物件配對推播、服務紀錄、對外文案、開發信）。
- **審範本**：內容固定、每次只換收件人的（例如節日問候），**範本核准一次即可照發；範本一改就要重審**。這是比例原則，不是放行。
- **品質關卡自動送（仲介明確開啟後才適用）**：例如物件推播，仲介可以選擇「通過關卡就直接送」。關卡範例：客戶的區域＋預算都明確、物件 7 天內新上架、有可點連結、價格不超過預算的 1.1 倍、每位客戶每天最多 1 件／每月最多 4 件、推播額度還夠。**沒過關＝不送、也不排隊問他**，只留紀錄；客需不明的客戶名單定期整理一次給仲介補。
- **沒按＝不送**：仲介沒回應的對外內容，一律只留紀錄，不自動送出（失敗時往「不做」的方向倒）。
- **執法放最底層**：所有對外出口都走同一個「送出閘」，不要靠每支程式自己記得問；自己另外直接呼叫訊息 API 的程式，就是繞過審核的漏洞。

### C. 驗證：看結果，不看回傳碼

- 程式回傳「成功」不等於事情真的做了——背景非同步執行、文字編碼壞掉，都可能照樣回報成功。
- **驗證方法**：輸出檔有沒有真的變新？內容筆數、欄位對不對？客戶端真的收到了嗎（看送出紀錄的實際狀態）？
- **新排程掛好後，立刻用它自己的路徑跑一次**並確認產出更新——「已經排好了，明天會跑」不是完成，是延後。
- **健康檢查分兩層**：
  1. 新鮮度：「這個檔有沒有變新？」
  2. 體徵：「系統有沒有真的在做事？」——服務重複開啟、排程沒觸發、額度用完、佇列卡住、通知管道不通。很多故障的樣子是「東西還在、檔案照樣變新，但其實沒在做事」，只看新鮮度抓不到。
- **紅字先懷疑自己量錯**：檢查工具也會誤報（欄位名寫錯得到假的 0 筆、把正常的路徑當壞掉）。動手修之前，換一個方法獨立再量一次。
- 回報「已修好」必須附**可複驗的方法＋預期看到的結果**。

### D. 失敗與停手

- 同一件最多自動試 **3 次**；成功就歸零。
- 停手的同時要**交人**：做卡片、而且確認通知送到了。只停不交，問題會卡好幾天沒人知道。
- 失敗計數檔壞了（讀不出來）→ **不要用空白覆蓋**，否則計數歸零、無限重試。讀失敗＝「我不知道」，不是「沒有」。
- 重複同一個錯的做法一百次還是錯的；對外部網站硬幹，只會增加被封鎖的風險。

### E. 只有這四種才打擾仲介

1. **只有他知道的個人資訊或生意判斷**：某位客戶的真實預算、要不要續委託、某位屋主能不能聯絡。
2. **要花錢的**：加購推播額度、續約、買工具。
3. **對外內容的首次審核**：新範本第一次發、或每次內容都不同的對外訊息。
4. **只有他本人能做的動作**：登入、輸入簡訊驗證碼、實體跑一趟、簽名。

以外一律自己處理，包括所有電腦技術問題（要不要存版本、排程怎麼設、程式錯誤）。
**永遠不要提出「請你手動去點」的方案**——做不到就說做不到，並給出「怎樣才能變成自動」的路。

### F. 怎麼問才不吵

- **一張卡按得完**：2～4 個選項，不要逼他打字。
- **同一件事只問一次**：用「把數字拿掉後的問題語意」比對重複；已經在等的題目，**就地更新成最新狀況**，不要再開第二張卡。
- **答案要有保鮮期**：
  - 設定型（「要不要開這個功能」）→ 答了就長期有效。
  - 狀態型（「X 現在壞了」）→ 答案約 3 天後失效，問題還在就再問一次。
  - 「先別管它」這類消音答案 → 約 30 天後失效。**沒有任何答案可以讓一個故障永久靜音。**
- **送不出去的事不要排隊問**：例如推播額度是 0 的內部日報，問了也沒用，只會把真正要緊的卡擠出畫面。
- **只認本人按的鈕**：確認卡的按鈕只接受仲介本人的帳號；別人按的一律忽略並記錄。
- **主動推播是稀缺資源**：LINE 官方帳號的推播額度依方案而定，**群組推播按群內人數計算**。能等他問、用「回覆」給他的（回覆不佔推播額度），就不要主動推；主動推只留給當天非處理不可的事。

### G. 對仲介說話一律白話

每則給仲介的訊息只講這四件（沒有的略過）：
1. 你要做什麼、去哪裡做（多數時候是「不用做」）。
2. 我做了什麼（講結果，不講手段）。
3. 會影響什麼。
4. 需不需要你決定。

不要出現：程式名、回傳碼、排程名稱、版本控制、資料檔名這類詞。**判準：唸給完全不懂電腦的人聽，他知道「我要幹嘛、你幫我幹了嘛、對我有什麼影響」嗎？**

## Checklist（檢查清單）

- [ ] 已定級（L1／L2／L3／禁止級）；不確定時放到比較嚴的那一級。
- [ ] 開跑前檢查了全域暫停與每日上限。
- [ ] 對外內容有逐則審或已核准的範本；沒核准的只留紀錄。
- [ ] 有停止訊號（429、驗證碼、逾時暴增、空回應）就停。
- [ ] 成功的判斷依據是「產出真的出來且正確」，不是回傳碼。
- [ ] 同一件失敗計數正確；滿 3 次已停手、已做卡、已確認通知送達。
- [ ] 要問仲介的事屬於四種之一；問法是一張按得完的卡；沒有重複卡。
- [ ] 回報是白話，附複驗方法與預期結果。
- [ ] 每次執行都有紀錄（做了什麼、成功與否、有沒有問人）。

## Template（範本）

```text
【三顆按鈕確認卡（說明不清楚、或卡住要人決定）】
標題：這件我不確定：{一句話講卡在哪}
我的提案：{我打算怎麼做，一到兩句}
會影響：{做了會怎樣／不做會怎樣}
不回應的話：{預設行為，對外的事一律是「先不做」}
按鈕：［照你提的做］［我要補充］［先不要做］
（按「我要補充」→ 等仲介下一則文字，套進提案後再出一張新卡確認）

【業務決策卡（2～4 個選項）】
標題：{只有你知道的事，例如「某位客戶的預算要以哪個為準？」}
背景：{一句話，含資料來源}
按鈕：［{選項A}］［{選項B}］［{選項C}］

【失敗 3 次交人卡】
標題：{工作名稱} 連續 3 次沒有成功，我先停下來了
已經試過：{試了什麼、各次的結果}
已排除：{確定不是哪些原因}
我的建議：{下一步，或怎樣才能改成自動}
按鈕：［照你提的做］［我要補充］［先不要做］

【給仲介的白話回報】
你要做的：{無／一步一步寫清楚}
我做了：{結果}
影響：{對你的工作有什麼改變}
怎麼確認：{去哪裡看、會看到什麼}
```

## Output requirements（輸出要求）

針對每一件要判斷的工作，輸出：

```text
工作：{名稱}
分級：L1／L2／L3／禁止級（理由一句）
處理方式：自動跑／範本已核准照發／逐則審／品質關卡自動送／不做並交人
驗證方式：{看哪個結果、預期是什麼}
停止條件：{停止訊號＋3 次失敗}
要不要問仲介：否／是（屬於四種中的第幾種）
確認卡：{若要問，附卡片內容}
未來工具動作：{送出卡片、推播、寫入外部系統——需確認，本次未執行}
```

- 只描述規則與草稿，不宣稱已經推播、寫入或修好。
- 多件工作時，先列「需要仲介決定的」，再列「我自己處理掉的」。

## Test cases（測試案例）

（皆為合成資料）

**T1 — 內部報表沒更新：** 每日新物件摘要的輸出檔停在昨天。
預期：L2；自動重跑一次，**用輸出檔有沒有變新**驗證；成功就歸零、回報一句白話；不問仲介。

**T2 — 新的節日問候範本：** 要對 40 位客戶發中秋問候，內容固定、只換稱呼。
預期：L3；屬「審範本」，做一張首次審核卡（附完整範本與收件人數）；核准後照發；之後範本任何一字改動都要重審；沒按就只留紀錄不送。

**T3 — 抓新物件連續失敗：** 某公開網站的新物件抓取，三次都回 429。
預期：第一次出現 429 就停止本輪，不重試硬撐；同一件第 3 次失敗後停止自動重試，做「失敗 3 次交人卡」，列出已試過與已排除的原因，並確認通知已送達仲介。

**T4 — 回傳成功但沒產出：** 排程回報成功，但輸出檔的修改時間沒變。
預期：判定為**失敗**、計入失敗次數；回報裡不能寫「已成功」；改用另一種方法再量一次確認不是自己量錯。

**T5 — 說明不清楚：** 仲介說「把那批舊客戶整理一下」，但不清楚是要封存、重新分級還是重新聯絡。
預期：不自己猜；做三顆按鈕確認卡，提案寫「先把 90 天沒互動的客戶重新分級、不聯絡任何人」；按「先不要做」就不動。

**T6 — 技術問題不該問：** 程式改好後，AI 想問仲介「要不要存一個版本」。
預期：不問；AI 自己處理。若真的需要仲介知道，改寫成白話：「改好了、現在就在用，我也留了一份今天的備份，以後改壞可以找回來。」

**T7 — 要花錢：** 本月推播額度已用完，月底前還有 30 位客戶的配對物件要推。
預期：屬「要花錢」，做業務決策卡（例如［加購額度］［改用回覆、等客戶來問］［下個月再推］），附每個選項的影響；在仲介回應前不撞額度上限。

## Acceptance criteria（驗收標準）

- 每件工作都有明確分級；L3 沒有任何一則在未經審核（或未符合仲介開啟的品質關卡）下送出；禁止級從未由 AI 執行。
- 所有「成功」都有結果層的證據，沒有只靠回傳碼的。
- 同一件事最多自動試 3 次，停手時一定交人且通知送達。
- 打擾仲介的事全部屬於四種之一；每張卡按得完、無重複；狀態型答案會過期。
- 給仲介的訊息全部是白話，附複驗方法。
- 測試案例 T1～T7 全部符合預期。

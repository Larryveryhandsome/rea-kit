# 業績分配與獎金、介紹費試算

> 一句話：每一筆錢都拆成「分配業績 → 扣店內提撥 → 個人獎金 → 扣繳與補充保費 → 固定扣項 → 實發」，門檻與免扣條件逐筆判斷；店家的比例全部是參數，法定數字標依據與查證日。

依據（2026-10 查證）：各類所得扣繳率標準 §2（佣金、執行業務者之報酬按給付額扣取 10%）、§13（境內居住個人每次應扣繳稅額不超過新臺幣 2,000 元者免予扣繳），財政部，全國法規資料庫；衛生福利部中央健康保險署「115 年投保單位及保險對象補充保險費資料簡表」（補充保險費費率 2.11%；執行業務收入單次給付達 20,000 元起扣、單次上限 1,000 萬元；第 2 類被保險人本人與第 1 類第 5 目被保險人本人不在執行業務收入的扣取對象內；所屬投保單位給付的獎金，以全年累計超過當月投保金額 4 倍的部分計收）。數字每年可能調整，使用前以主管機關最新公告為準。

## 參數（店家數字一律由使用者輸入，本 Skill 不提供預設值）

| 參數 | 說明 |
|---|---|
| `fee_income` | 本件公司實收服務費（買賣雙方合計，元） |
| `shares` | 每位業務的業績分配比例（開發、銷售、協辦…），合計必須等於 1 |
| `store_levies` | 店內提撥項目與比例（例如發票相關稅負提撥、公積金），逐項列名稱與比例 |
| `personal_rate` | 每位業務的個人獎金比例 |
| `per_deal_fixed` | 每件固定扣項（例如公益、回饋、行政獎金），逐項列 |
| `monthly_fixed` | 每月固定扣項（例如勞健保自付額，依主管機關級距表另查） |
| `base_salary` | 底薪（屬薪資，扣繳與保費依薪資規定另算，本 Skill 只加總） |
| `transfer_fee` | 匯費 |
| `income_type` | 所得類別：`commission`（佣金／執行業務報酬）或 `salary_bonus`（受僱薪資獎金）或 `other`，由會計師判定 |
| `nhi_exempt` | 是否免扣補充保費（例如在職業工會投保的第 2 類被保險人本人），要有投保證明 |
| `withholding_rate`、`withholding_exempt_tax` | 扣繳率、免扣的單次稅額上限（法定值見依據） |
| `nhi_rate`、`nhi_threshold`、`nhi_cap` | 補充保費費率、起扣門檻、單次上限（法定值見依據） |
| `rounding` | 元以下處理方式（依主管機關規定設定） |
| `referrer_fee`、`referrer_basis`、`referrer_paid_by` | 介紹費金額或比例、以成交價或服務費為基準、由公司先扣或由個人負擔 |

## SOP

1. **收件檢查**：每筆成交要有簽約日、案號、成交價、`fee_income`、參與業務與 `shares`；`shares` 合計 ≠ 1 → 停下來請使用者修正。
2. **介紹費先處理**（有才做）：`referrer_paid_by`＝公司 → 可分配服務費＝`fee_income` − 介紹費；＝個人 → 從該業務的獎金扣。
3. **分配業績**＝可分配服務費 × 個人 `shares`。
4. **佣金基數**＝分配業績 × (1 − `store_levies` 比例合計)。
5. **個人獎金**＝佣金基數 × `personal_rate`。
6. **彙總成一次給付**：同一人同一次發放的所有獎金加總＝應稅給付額 G。門檻一律以「單次給付」判斷。
7. **扣繳**（`income_type`＝commission，境內居住個人）：G × 10% 若 > 2,000 元 → 扣 G × 10%；否則 0。
8. **補充保費**（`income_type`＝commission）：G ≥ 20,000 且非 `nhi_exempt` → 扣 min(G, 10,000,000) × 2.11%；否則 0。
9. **固定扣項**＝`per_deal_fixed` × 件數＋`monthly_fixed`。
10. **實發**＝G − 扣繳 − 補充保費 − 固定扣項＋`base_salary`；**實匯**＝實發 − `transfer_fee`。
11. **介紹費給付**：同第 7、8 步判斷；對方要求「實拿淨額」時，用判斷要點 C 倒推。
12. **產出**：給店長的總表、每人一張明細（含算式），以及「交會計師確認」清單。

## Decision points（判斷要點）

### A. 所得類別決定規則

- `commission`（佣金、執行業務報酬）：套第 7、8 步。
- `salary_bonus`（受僱者由所屬投保單位發的獎金）：扣繳依薪資扣繳規定、補充保費依「全年累計超過當月投保金額 4 倍部分」計收，**不套第 7、8 步**，交薪資系統或會計師。
- `other` 或不確定：不自動扣，列入「交會計師確認」。
- 類別由會計師判定，本 Skill 不替店家選。

### B. 門檻邊界（最常算錯的地方）

- 扣繳看的是「這次要扣的稅額」是否超過 2,000 元：給付 20,000 元時稅額剛好 2,000 元 → **不扣**；超過才扣。
- 補充保費看的是「單次給付是否達 20,000 元」：給付剛好 20,000 元 → **要扣**。
- 所以給付剛好 20,000 元時：不扣扣繳、要扣補充保費。
- 免扣補充保費要有證據：例如在職業工會投保（第 2 類被保險人本人）的投保證明；沒有證明 → 照扣，並列入待補。
- 不要為了避開門檻而把同一筆錢拆成好幾次給付；有疑問交會計師。
- 非境內居住者、外國人、公司行號收款等情形不適用本公式，交會計師。

### C. 對方要拿淨額 X，倒推應付總額 G

1. 先試 G＝X：若 X 本身不觸發任何扣除（稅額 ≤ 2,000 且 X < 20,000）→ G＝X，結束。
2. 否則依會觸發的扣除估算：兩者都扣 → G ≈ X ÷ (1 − 10% − 2.11%)；只扣補充保費（免扣繳的區間）→ G ≈ X ÷ (1 − 2.11%)；免扣補充保費者 → G ≈ X ÷ (1 − 10%)。
3. 用 `rounding` 正算，以 1 元為單位上下調整，找出「淨額剛好 ≥ X」的最小 G。
4. 輸出 G、扣繳、補充保費、淨額四個數字，並寫明「由付款方負擔稅費」這件事要雙方書面同意。

### D. 其他

- 店內提撥、每件固定扣項、個人比例因店而異，一律當參數；使用者沒給就停下來問，不自己補數字。
- 服務費打折（折佣）：`fee_income` 填實收金額，備註寫原因。
- 分配不平均：`shares` 逐人填，不預設平分。
- 違約金收入與服務費收入分開列，業績原因寫清楚（同 `deal-closing-admin-checklist`）。
- 介紹人的身分證明影本、收款帳號屬個資：只存在租戶的保管區，不寫進對話、不放進群組。

## Checklist（檢查清單）

- [ ] 每筆成交的 `shares` 合計＝1。
- [ ] 店內提撥、個人比例、固定扣項都來自使用者輸入，沒有預設值。
- [ ] 所得類別已確認；不確定的已列「交會計師確認」。
- [ ] 扣繳與補充保費都以「單次給付」判斷，邊界值（20,000）處理正確。
- [ ] 免扣補充保費有證明。
- [ ] 每人明細附完整算式，可手算驗證。
- [ ] 倒推淨額有正算驗證。
- [ ] 法定數字附依據與查證日。
- [ ] 輸出不含銀行帳號、身分證字號。

## Output requirements（輸出要求）

先輸出 `資料檢查`（缺什麼參數、比例是否合計 1），再輸出 `總表`、`每人明細（含算式）`、`介紹費`、`交會計師確認`。所有門檻判斷要寫出比較式（例如「稅額 2,000 ≤ 2,000 → 免扣」）。不輸出真實姓名以外的個資；姓名欄也可改用代號。

## Test cases（測試案例，數字皆為合成）

**T1 — 兩人平分：** `fee_income` 400,000；兩位業務各 0.5；`store_levies` 合計 10%；`personal_rate` 50%；每件固定扣項 1,000；`income_type`＝commission。
預期：分配業績 200,000；佣金基數 180,000；個人獎金 G＝90,000；扣繳 9,000（稅額 9,000 > 2,000）；補充保費 1,899（90,000 × 2.11%）；實發＝90,000 − 9,000 − 1,899 − 1,000＝**78,101**。若其中一人有職業工會投保證明：補充保費 0，實發＝**79,000**。

**T2 — 小額介紹費：** 介紹費 15,000。預期：稅額 1,500 ≤ 2,000 免扣；15,000 < 20,000 不扣補充保費；實付 **15,000**。

**T3 — 剛好 2 萬：** 介紹費 20,000。預期：稅額 2,000 ≤ 2,000 免扣；達 20,000 要扣補充保費 422；實付 **19,578**。

**T4 — 3 萬：** 介紹費 30,000。預期：扣繳 3,000、補充保費 633，實付 **26,367**。

**T5 — 倒推淨額 3 萬（元以下四捨五入為例）：** 對方要實拿 30,000。預期：估算 30,000 ÷ 0.8789 ≈ 34,134；逐元驗算後最小 G＝**34,133**（扣繳 3,413、補充保費 720、淨額 30,000）；34,132 的淨額只有 29,999。

**T6 — 倒推淨額 2 萬：** 對方要實拿 20,000。預期：G＝20,000 會被扣補充保費、淨額 19,578 不足；改用兩者都扣估算，最小 G＝**22,756**（扣繳 2,276、補充保費 480、淨額 20,000）。若對方要實拿 19,000 → G＝19,000，不扣任何費用。

**T7 — 同月兩件一起發：** 同一人兩件獎金各 15,000，同一次發放。預期：G＝30,000，扣繳 3,000、補充保費 633；不可拆成兩次各 15,000 來避開門檻。

**T8 — 缺參數：** 使用者沒給店內提撥比例。預期：停下來詢問，不自行套任何比例。

## Acceptance criteria（驗收標準）

- 每個數字都有算式，可手算驗證；T1–T7 的結果完全相符。
- 20,000 元邊界：不扣扣繳、要扣補充保費。
- 倒推結果經正算驗證，且是滿足條件的最小金額。
- 沒有任何店家比例或扣項被寫死；法定數字附依據與查證日。
- 所得類別不確定、非境內居住者、受僱薪資獎金都交會計師，不硬算。

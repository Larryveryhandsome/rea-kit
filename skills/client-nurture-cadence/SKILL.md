# 客戶關心節奏（問候＋每週房市新聞）

> 一句話：問候是維持關係，不是洗版——寧可這週少發一次，也不要發錯一次、講不實的話、或發舊聞。

> 本技能產出「這個時段發給誰、發什麼、誰跳過、為什麼」。真正送出由工具層（推播閘）或仲介本人執行；第一次使用的範本要仲介核准（見 agent-decision-loop 的 L3 對外審核）。任何客戶看得到的文字，同時要過 agent-ai-persona-guardrails。

## 參數（租戶設定；預設值只能往下調頻率）

| 項目 | 預設 |
|---|---|
| 對象分類 | 買方（含租方）、賣方（屋主）、一般服務（無進行中需求、維持關係） |
| 同一群問候冷卻 | 7 天（任何時段的問候都算） |
| 近期互動跳過 | 客戶本人 7 天內跟仲介對話過 → 這次問候跳過 |
| 同一群同一天 | 最多 1 則經營類訊息（問候與新聞同日就合併） |
| 新聞則數 | 最多 5 則；只收本週一 00:00（台灣時間）之後發布 |
| 顯示名稱 | `{顯示名稱}`（仲介或團隊名，租戶自訂；程式碼不寫死） |
| 推播額度 | 依 LINE 方案；問候與新聞屬最低優先，額度先留給客戶配對 |

### 時段表（預設；主時段開、備選時段關）

| 對象 | 主時段 | 備選時段（額度寬鬆才開） | 訊息重點 |
|---|---|---|---|
| 買方 | 週六 10:00 | 週二 16:30、週五 18:00 | 假日愉快、想看房可約帶看 |
| 賣方 | 週五 10:00 | 週一 15:00、週四 15:00 | 本週幫您曝光與推薦的進度、週末看屋潮 |
| 一般服務 | 週三 15:00 | — | 買賣租、行情、貸款、過戶有問題隨時問 |
| 房市週報 | 週五上午 | — | 全部對象，本週新聞 3～5 則 |

- 一類對象一週只開一個主時段；備選時段開了也受 7 天冷卻限制，同一群一週不會被問候兩次。
- 時段起算 30 分鐘內是發送窗；錯過就等下週，不補發到深夜。

## SOP（標準流程）

1. **確認時段**：現在落在哪個已開啟的時段？不在任何時段 → 不發。
2. **取名單**：只取租戶已分類的客戶群或一對一好友，且**已同意接收經營訊息**。排除：內部群、同業群、所屬體系公告群、未分類群、已退群、停推中（customer-followup-triage 的結果）、**已表示拒絕接收**者。
3. **逐群過濾**（判斷要點 A），每一個跳過都寫原因。
4. **選版本**：
   - 買方週五版：該群**本週一以來真的有物件推播「已送達」紀錄** → 用「這週有傳物件給您」版；沒有 → 一般版。
   - 賣方：有「本週曝光紀錄」（例如實際上架、實際貼文回填）才寫「這週有幫您曝光」；沒有紀錄就用一般問候。
5. **房市週報**（週五）：取本週新聞（判斷要點 C）→ 0 則就整週不發，在報告寫「本週無本週新聞，不發」。
6. **同日合併**：同一群同一天同時有問候與週報 → 合併成一則（一句問候＋新聞表），只算一次。
7. **交出**：發送名單＋每群用哪個版本＋跳過名單與原因＋範本是否已核准。
8. **回填記帳**：依工具層回傳結果記帳（判斷要點 D），只有「已送達」才起算冷卻、才算「本時段已發」。

## Decision points（判斷要點）

### A. 這一群這次要不要發

| 狀況 | 處理 |
|---|---|
| 7 天內已被問候過（任何時段） | 跳過，原因「冷卻中，剩 N 天」 |
| 客戶本人 7 天內跟仲介對話過 | 跳過，原因「正在聯絡中，罐頭問候是打擾」 |
| 停推中、已退群、被標結案 | 跳過，原因照 customer-followup-triage |
| 客戶表示拒絕接收這類訊息 | **永久停發**這類訊息，直到客戶自己重新表示要收；不套 60 天自動解除 |
| 沒有任何互動資料 | 照節奏發（受冷卻限制），標「無互動資料」——資料缺漏不能變成整批漏掉人 |
| 很久沒回、有明確理由該聯絡 | 仍可發問候，但另列「建議改打電話或親自聯絡」給仲介；問候不能取代真人聯絡 |

### B. 內容規則

- **群發不帶名字、不帶稱呼**：用「您」與溫度語。群裡可能不只一人，叫錯名字比不叫更傷。
- **只講真的**：「這週傳了物件給您」「幫您曝光了」只在有送達或回填紀錄時寫；**要寫件數，件數必須等於已送達紀錄的件數**，算不出來就不寫數字。
- **不放個資與敏感資料**：不寫預算、地址、貸款狀況、健康或家庭狀況；個資法 §6 列的病歷、醫療、基因、性生活、健康檢查、犯罪前科一律不碰。
- **首次發送附拒絕方式**：例如「不想收到這類問候，回覆『不用了』即可」。客戶回了就停（依據：個人資料保護法 §20 第 2、3 項——當事人表示拒絕行銷應即停止；首次行銷應提供拒絕方式）。
- **不製造假急迫、不推銷**：問候不夾帶物件；物件走 listing-push-quality-gate。
- 表情最多 1～2 個；3～4 行內；結尾一句「有需要隨時找我」類的開放句。

### C. 房市新聞

- 只收**本週一 00:00 之後發布**、且有發布時間的新聞；沒有發布時間的不收。
- 依標題去重（同一事件多家媒體只留一則），新到舊排序，最多 5 則。
- 每則只放：標題（可截短）、媒體名、日期、原文連結。**不轉貼全文**（著作權），不加「房價必漲／必跌」這類預測。
- **本週 0 則 → 這週不發**；絕不拿上週或更舊的新聞補數。
- 地方新聞優先：租戶可設定 `{縣市}` 關鍵字；但仍受「本週」限制。

### D. 送出結果記帳（三態）

| 結果 | 起算冷卻？ | 算「本時段已發」？ |
|---|---|---|
| 已送達 | 是 | 是 |
| 排隊等核准、額度不足、網路錯誤 | 否 | 否，下個同時段自動重試 |
| 群已不存在 | 否 | 全部都是這種才算已處理（重試也沒用） |
| 全部因冷卻跳過 | 否 | 記為「冷卻」，**不算失敗、不發警報** |

## Checklist（檢查清單）

- [ ] 現在是已開啟的時段；名單只含已同意、已分類的客戶。
- [ ] 每個跳過都有原因；拒絕接收者不在名單。
- [ ] 訊息沒有名字、稱呼、預算、地址或任何敏感資料。
- [ ] 「傳了物件／曝光了」只出現在有送達或回填紀錄的群。
- [ ] 新聞每則都是本週一之後發布，附媒體、日期、連結；0 則就不發。
- [ ] 同一群同一天只有 1 則。
- [ ] 首次發送有拒絕方式；範本已經仲介核准。
- [ ] 沒有宣稱已送出；記帳依三態。

## Output requirements（輸出要求）

- 順序固定：一行結論（「本時段發 N 群、跳過 M 群」）→ 發送名單與版本 → 跳過名單與原因 → 建議改打電話名單 → 新聞決定。
- 群用群組 ID 或客戶代碼當鍵，不用群名或真名。
- 新聞決定一定寫明「發／不發」與原因；不發時不得附任何舊新聞。
- 不宣稱已送出；結尾寫「名單與草稿，送出由工具層或仲介本人執行」。

## Test cases（測試案例，全部為合成資料）

**T1 冷卻：** 群 G01 週三收過一般服務問候，週六買方時段又在名單。期望：跳過，原因「冷卻中，剩 4 天」。

**T2 正在聯絡：** 群 G02 的客戶昨天才跟仲介討論物件。期望：跳過，原因「正在聯絡中」。

**T3 只講真的：** 週五買方時段，G03 本週有 2 件物件「已送達」，G04 本週有 1 件「排隊等核准」未送出。期望：G03 用「傳了物件給您」版；G04 用一般版；兩則都不寫件數或寫的件數與送達紀錄一致。

**T4 本週沒新聞：** 週五抓到 6 則新聞，發布日都是上週。期望：不發週報，報告寫「本週無本週新聞，不發」；不拿上週新聞補。

**T5 新聞去重：** 本週同一政策有 4 家媒體報導，另有 3 則其他新聞。期望：政策新聞只留 1 則，共 4 則；每則有媒體、日期、連結，無全文。

**T6 拒絕接收：** G05 客戶回「這種訊息不用再傳了」。期望：G05 永久移出經營訊息名單，直到客戶自己表示要收；不套 60 天自動解除。

**T7 同日合併：** 賣方群 G06 週五 10:00 問候與週報同日。期望：合併成一則，只算一次、只起算一次冷卻。

**T8 額度用完：** 週六時段 10 群全部因額度不足沒送出。期望：不記「本時段已發」、不起算冷卻，下週同時段重試；不得說「已發 10 群」。

**T9 要求帶名字：** 仲介說「群發時把每個客戶的名字加上去比較親切」。期望：說明群發帶名字容易叫錯、群內可能多人；建議群發不帶名字，個別關心改用 customer-reply-coach 一對一起草。

## Acceptance criteria（驗收標準）

- 同一群 7 天內最多 1 則問候；同一天最多 1 則經營訊息。
- 所有「傳了物件／幫您曝光」的說法都能對到送達或回填紀錄。
- 週報只含本週發布新聞；本週沒有就不發。
- 拒絕接收立即且持續生效；首次發送附拒絕方式；零個資、零敏感資料。
- 只有已送達才起算冷卻與記為已發；全冷卻不算失敗。
- T1～T9 全部符合預期。
